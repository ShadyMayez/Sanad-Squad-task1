# System/task message integration

`WriterAgent`, `ReviewerAgent`, and `SemanticVerifier` now build `[SystemMessage, HumanMessage]` using `langchain_core.messages`. The system content is read from editable instruction Markdown. The Writer's human JSON contains the current slot, full brand rules, source metadata and pinned quotations, and revision feedback. The Reviewer's human JSON contains the current Draft, measured tweet count and lengths, source quotations, prose brand guidance, deterministic errors, and a compact atomic-verdict brief. Python enforces the full brand-rule JSON. `LocalModel.structured` passes those messages directly to `ChatOllama.with_structured_output`; it also accepts a legacy string for compatible direct callers. The same model instance controls Pydantic parsing, request timeout, bounded transport retry, token extraction, and shared per-loop concurrency.

The message boundary is tested by inspecting actual message object types and confirming source quotations appear only in the human message. The Reviewer is passed the separate atomic verdicts and its Python postcheck forces a rejection for any adverse verdict. A high-score rejection with no failed gate triggers one bounded consistency re-evaluation, never a forced approval. The graph also checks the final semantic state before Visual, and export preflights it again. These gates remain meaningful even if a lower-trust quote asks the model to change roles or approve content.

This is a trust-boundary improvement, not a proof of prompt-injection immunity. The live synthetic attack results and any failures are recorded separately. JSON serialization uses `ensure_ascii=False` and no silent evidence truncation. A too-large context remains a documented failure risk for the local 4B model.

# Source-authority correction after live piece

The first real closure piece showed the Writer importing a KB `root_cause` summary into public copy even though its pinned quotation did not establish that exact causal assertion. The Writer task now carries the researched topic and a reduced evidence record, without legacy `description`, `root_cause`, or `excerpt` summaries. The Reviewer receives the same source-only record. Those KB fields remain intact for the PDF contract and topic management, but only `source_quote` is admissible for factual post wording. This also removes redundant task tokens. The rejected piece and its measured usage are retained under `output/semantic-final-piece/`.
