# Prompt architecture design

LLM agents will receive real LangChain `SystemMessage` and `HumanMessage` objects. Versioned Markdown is the trusted system instruction. Dynamic task data is one JSON-serialized human message, including the slot, topic, brand rules, pinned source quotations, draft, reviewer feedback, and semantic report as appropriate. No source excerpt is interpolated into the system instruction. The system message explicitly says source text is untrusted data. `LocalModel.structured` accepts both the new message list and legacy strings so external callers are not broken; the same ChatOllama client, semaphore, timeout, retries, Pydantic parser, and usage extraction remain in use.

The technical and marketing writer prompts will define distinct audiences, mission, boundaries, short procedures, output contracts, examples, and uncertainty behavior. The reviewer will define six dimension-specific score anchors, independent claim assessment, and actionable feedback. The semantic verifier keeps its dedicated role and five-label output. Research stays deterministic. The Visual Agent uses a deterministic, evidence-aware specification strategy rather than an extra model call: it receives the accepted final draft and supported atomic claims, chooses a diagram pattern by researched vulnerability type, and names only mechanisms present in the verified content.

Dynamic JSON stays traceable and is never silently truncated. The configured context window is 8,192 tokens; if source quotations or claims exceed the model's effective capacity, structured generation may fail and the slot must fail or drop rather than silently omit evidence. A future token-aware relevance selector could improve this. The PDF's one-revision limit, accepted-only visual path, and exact CSV output remain authoritative.

# Two-pass semantic support check

The Semantic Verifier's first model call judges each independent atomic claim against pinned source quotations and selects exact source-span option IDs for tentative support. A second, skeptical call receives only those selected spans, the full claim, and a separate trusted instruction file (`instructions/semantic-skeptic.md`). It has veto authority, not publication authority. This added call was justified by benchmark case L, where the initial model inferred a stronger reentrancy-lock guarantee from adjacent remediation terms. The additional prompt is compact, and only tentative SUPPORTED claims incur the extra request. Python records both calls' token usage and treats audit errors as non-support.
