# Semantic verifier architecture

The per-slot LangGraph route is now Research → Writer → deterministic atomic extraction → pinned provenance validation → independent semantic verifier → Python hard validation and Reviewer → decision → Visual or one revision/drop. Each new node has an explicit state handoff. The authoritative content revision counter remains `attempt`; transport retry in `LocalModel` is separate. The graph recursion bound increased to 22 to accommodate the extra nodes without allowing a third draft.

`content_pipeline/semantic_verification.py` reads `instructions/semantic-verifier.md` and receives one atomic claim plus pinned source quotations, metadata, and scope per call. It presents numbered exact source span options rather than asking the small model to retype quotation bytes. Python assigns claim and evidence IDs from the selected options. Tentative SUPPORTED decisions receive a second audit from `instructions/semantic-skeptic.md`, using only the selected spans and no first-pass rationale. This audit can veto support; an error fails closed. Both passes use the same `LocalModel.structured` service as Writers and Reviewer. The process shares one per-event-loop semaphore for the same endpoint/model. At default concurrency one, separate local CLI processes also share a POSIX file lock. A higher configured concurrency is scoped to a process and needs external coordination across processes.

The verifier returns the five requested labels. A SUPPORTED verdict must select exact verbatim supporting spans found in the pinned `source_quote`; unknown, missing, fabricated, or malformed selected IDs become VERIFICATION_ERROR. Provenance failure is checked before model invocation. Confidence is diagnostic only. Model judgment evaluates meaning, scope, causality, negation, conditions, numerical facts, and named technical identity. Neither substring checks nor two model judgments are treated as a truth proof.

The Reviewer remains distinct. Its prompt contains the full semantic report and it still scores the written rubric. Python forces its `approved` flag false for any non-SUPPORTED atomic verdict or hard validation failure, and the graph separately checks the semantic gate before Visual. The exporter preflights final approval, empty hard errors, complete supported verdict coverage, valid visual specification, and provenance status **before** creating a run directory. Source text is always marked untrusted data. Unsupported or contradicted content supplies targeted feedback for one correction and a second full pass; persistent content rejection drops permanently. A source-provenance failure or verifier execution/structured-output error marks that slot failed without spending a content revision attempt.
