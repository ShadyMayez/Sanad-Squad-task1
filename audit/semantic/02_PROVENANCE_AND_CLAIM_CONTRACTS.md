# Evidence provenance and atomic claim contracts

`kb.json` keeps every original PDF-required vulnerability field. Each evidence item now additionally records title, source type and URL, a local normalized text snapshot path, SHA-256 of its bytes, retrieval date, exact source quotation, code-point start/end offsets, and scope note. `source_snapshots/README.md` credits all 17 pages and distinguishes the prior local `excerpt` summaries from actual source quotations. `scripts/update_source_snapshots.py` is an explicit maintenance command; ordinary generation is offline and never silently refreshes a source.

`content_pipeline/provenance.py` rejects missing fields, missing or escaping paths, hash changes, wrong quote offsets, and quotations absent from a snapshot. `load_kb()` checks the KB shape globally. The per-slot provenance node checks selected source integrity after Research, so a missing or changed snapshot fails only that slot while unrelated slots continue. Hash integrity proves the locally pinned text was not modified, not that the upstream page remains current or true.

`content_pipeline/claim_extraction.py` reads **published tweet text** independently of Writer claim objects. It segments sentences and coordination clauses, records exact character spans, preserves the original proposition (no lossy normalization), and captures quantifiers, negation, conditional and numeric tokens. Each atomic claim receives a stable attempt-local ID, tweet index, sentence context, offsets, claim type, and candidate evidence IDs. Writer mappings supply candidate IDs, but cannot decide which text receives verification. An unmapped sentence or uncovered substantive text fails the gate; no replacement source ID is invented. Uncertain questions still receive verification. This conservative lexical segmenter can over-segment or miss subtle implicit claims; see report 07.

The persisted `claims.json`, `evidence_provenance.json`, `semantic_verification.json`, and `grounding_summary.json` have Pydantic models in `content_pipeline/schemas.py` and JSON schemas under `schemas/`. They permit a trace from final tweet text to atomic span, candidate source, pinned quotation, semantic verdict, reviewer result, and disposition.

# Live-run source correction

The first real technical piece exposed an incomplete SWC-107 quote that ended at “Use a reentrancy lock (ie.” even though the pinned page snapshot continued with the named example. The KB quote and its end offset were extended to the complete sentence already present in the same immutable snapshot. A second pass found the same abbreviation clipping in SWC-116 and extended it through the end of that sentence. Neither immutable snapshot hash nor source URL changed. Tests revalidated exact substrings and offsets. The maintenance script now preserves a complete sentence at a section boundary. These corrections do not make a source a proof of any particular mitigation mechanism or universal outcome.
