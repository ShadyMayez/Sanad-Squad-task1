# Real six-slot week: content and workflow inspection

Command: `.venv/bin/python run_week.py --plan plan.json --output output/relation-grounding-week`

Actual exit code: **1**. The run completed all six planned slots in **1,504.110 seconds**: **0 shipped, 6 dropped, 0 failed**. It recorded **203,991 prompt** and **25,418 completion tokens**, complete usage metadata, peak one concurrent Ollama call, and USD 0 external model API charges. Local electricity and hardware cost was not measured. The prior context-quality week took 1,006.454 seconds, 149,943 prompt tokens, and 14,543 completion tokens, with two shipped. This run took about 49% longer and shipped none. Different model drafts and review paths mean the entire increase cannot be assigned to the relation gate alone.

`inspect_runs.py` validated every persisted JSON contract, source provenance, plan order, exact CSV header, revision count, and export references. `posts.csv` contains only `Post Text,Image`; it has **no data rows**. `visual_specs/` is empty. This is correct fail-closed behavior for six dropped slots, but it is **not** a successful content-production sample.

Every final slot has exactly two drafts and two Reviews; the one-revision limit held. Six independent slots completed despite the `thread_2` Writer mapping failure. No rejected draft reached Visual generation or CSV. The run demonstrates orchestration, audit, isolation, and fail-closed export, while exposing poor useful-content yield and model over-rejection. No accepted public claim required clearance because there were no accepted pieces. The historical unsafe `thread_1` remains not publication-cleared.

The code should **not** be marked fully accepted as a reliable content pipeline on this evidence. Fixing the false-rejection pattern requires a separate development set and a fresh independently labeled holdout; simply loosening the gate to increase CSV rows would risk reviving the original causal false acceptance.
