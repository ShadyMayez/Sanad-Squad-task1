# Semantic context and content quality closure

## Root causes

The earlier `thread_3` attempt 2 used a real supported source relationship: OWASP SCWE-028 introduces a list of consequences with “This can lead to,” followed by “Loss of funds or data.” The first verifier saw the quotation, but the skeptical pass received only the isolated list item. It rejected a supported “may cause loss” claim. The previous Writer instructions also discouraged meaning-preserving paraphrase and led to near-copy drafts. The first revised week then exposed three narrower defects: a bounded context window was labeled `truncated` even when the byte budget was not the reason it was partial; Reviewer scoring treated an omitted mitigation as factual error; and a skipped semantic model call incorrectly marked usage measurements incomplete.

## Implemented changes

The skeptical pass receives exact selected spans together with bounded, hash-checked context, source scope, and absolute offsets. The first and skeptical decisions, proposed spans, and final disposition are saved separately. Python checks the source snapshot digest, quote offsets, context text, source identity, byte bound, and the new optional `window_partial` flag before accepted content is exported. A budget-limited `truncated` flag remains distinct. Disagreement fails closed; no Reviewer score can override it.

The Technical Writer can paraphrase source facts while preserving conditions, causal relationships, and certainty. Its guidance now calls out reentrancy callback wording and the oracle “for price data” qualifier. The Marketing Writer is instructed to return one complete claim record matching its entire public sentence. The Reviewer rubric separates factual correctness from usefulness and recognizes each `tweets` array element as a rendered tweet. It keeps the existing thresholds and one bounded consistency retry. A skipped semantic model call leaves measured usage from actual calls intact.

The final 60-case regression replay accepted 28 of 30 supported claims and none of 30 adverse claims; exact five-label accuracy was 47/60. It falsely rejected two source-attributed recommendations, including the previously known conditional `assert`/`require` case. A fresh 20-case holdout, frozen before its first final-code inference, accepted 8 of 10 supported and none of 10 adverse claims; exact label accuracy was 13/20. These meet the predeclared supported-recall, supported-precision, and adverse-false-acceptance thresholds, but the false rejections and label confusion are material limits. Six real source-text prompt-injection probes caused zero false accepts. All benchmark and holdout token metadata was available. Details and per-case reasons are in `05_SEMANTIC_BENCHMARK_RESULTS.md` and the saved JSON results.

The final-code standalone technical run dropped its six-tweet reentrancy thread after one revision when the skeptic rejected “critical state changes” against the source's “internal state changes.” It exported no content. The final-code marketing run shipped a grounded low-level-call review action. Both artifact inspectors passed. The prior calibrated standalone technical run had shipped a six-tweet thread, so the later drop illustrates local-model variance and a conservative false-negative risk. No content was forced through the gate to improve the count.

Finite local-model evaluations establish observed behavior only; they do not establish universal semantic correctness or eliminate the need for human review before publication.

## Final six-slot replay and acceptance verdict

The final local week completed with **2 accepted, 4 dropped, 0 failed** in **1,006.454 seconds**, recording **149,943 prompt** and **14,543 completion tokens** with complete usage metadata and peak one active Ollama call. External model API charges were USD 0; local operating costs were unmeasured. The exact accepted-only CSV has two rows with written-spec references. The independent artifact inspector passed the mechanical contracts. `07_REAL_OLLAMA_CONTENT_INSPECTION.md` reviews all six final drafts and reasons.

The engineering control-flow, bounded context, source integrity, one-revision rule, concurrency limit, output contracts, and real execution requirements are demonstrated. **Unqualified semantic acceptance is not met.** In the accepted reentrancy thread, tweet 3 says late state changes are “the core risk,” but its selected SWC-107 span is a mitigation instruction rather than an explicit root-cause statement. Both verifier passes and the Reviewer approved the inference. This is a real manual grounding concern and evidence that two LLM passes can share the same causal error. The accepted thread should receive a technical editor's correction or additional direct source support before publication. No generated artifact was rewritten to conceal this observation. The final verdict is **partial implementation success with a semantic-grounding defect**, not universal assignment compliance.

The concrete next step is a source-to-claim relation check that distinguishes descriptive causes from normative mitigations, backed by independent technical labels and a fresh held-out set. A corrected system must be rerun through the standalone and full-week gates before claiming that accepted output is publication-ready. Other residual limits include sparse KB entries, false rejections of source recommendations, five-label confusion, and unmeasured local hardware cost.
