# Expanded semantic benchmark protocol

`fixtures/benchmark.tsv` contains 60 individually written claim/evidence/expected-verdict labels. The first 40 rows are the development portion; the last 20 are held out from prompt editing. The file was frozen before this run. It contains 30 genuinely source-supported claims and 30 adverse claims across direct support, paraphrase, multi-sentence and conditional support, recommendations, causal relationships, unsupported consequences, guarantees, negation, mechanism confusion, version scope, and list context. Each claim is checked against a pinned source quotation rather than the KB's editorial summary.

Before reading held-out results, the evaluation thresholds were recorded in `run_benchmark.py`: supported recall at least 0.70, supported precision at least 0.90, and false acceptance rate at most 0.10. These are engineering signals, not publication guarantees. The script reports all five labels, category outcomes, latency, and actual Ollama token metadata. The old 20-case benchmark remains unchanged for comparison.

The labels are independent of the model's responses but were authored and reviewed in this engineering pass; a second independent smart contract security reviewer was not available. Some SWC snapshots describe historical compiler behavior. Their statements are evaluated at the pinned source's scope, not asserted as current Solidity behavior. The sample is small and curated; observed rates cannot establish general reliability.

The 60-case primary set has supported, contradicted, and insufficient-evidence reference labels. Four predeclared supplemental probes in `run_supplemental.py` exercise AMBIGUOUS (two synthetic pronoun references) and VERIFICATION_ERROR (two deliberately corrupted snapshot hashes), so every verdict class is exercised. The supplemental rows are reported separately from the 40/20 development/held-out split; ambiguous language may legitimately receive INSUFFICIENT_EVIDENCE instead, and such differences are disclosed rather than relabeled after execution.

The first 60-case run and four supplemental probes exposed a false acceptance on an ambiguous pronoun. Their complete original results are preserved as `benchmark-pre-coreference-results.json` and `supplemental-pre-coreference-results.json`. A prompt clarification was then made. The original 60-case labels remain unchanged and are replayed as regression/calibration evidence, but their last 20 rows are no longer treated as unseen for the revised prompt. A new 20-case set in `fixtures/heldout-v2.tsv` was written and frozen before evaluating the revised prompt. It has ten supported and ten adverse claims, primarily from OWASP-SC03 and SWC-114, and uses the same predeclared precision, recall, and false-acceptance thresholds.

The first revised weekly run subsequently exposed a misleading context flag and content-scope errors. The 60-case set is being replayed again unchanged as regression evidence. A second 20-case set in `fixtures/heldout-v3.tsv` was written and frozen before any model call on those exact claims after the final partial-window and prompt changes. It contains ten source-supported and ten adverse cases targeting reentrancy, access control, oracle scope, failed calls, and conditional assert guidance. Its labels were assigned by this engineering pass and have not been externally double reviewed. The v3 script uses the same thresholds; no prompt or label changes will be made in response to its outcomes.
