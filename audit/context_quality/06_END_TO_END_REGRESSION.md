# End-to-end regression

The repository's deterministic suite passed **86 tests** with `.venv/bin/python -m pytest -q` after the context and prompt changes. This includes the original 68, 17 focused context-quality cases, and one regression for usage accounting when semantic inference is skipped. No prior test was removed or disabled.

The new cases check the saved `thread_3` source relation, first and skeptical pass persistence, independent veto after tentative support, two selected spans, bounded/truncated windows, exact snapshot offsets and hashes, source identity and scope mismatch, tampered-context export rejection, source-text injection through a forged quotation, fail-closed initial uncertainty, cross-source proximity veto, conflicting neighboring source statements, all active KB windows, loading the old release artifact with the additive schema, and an exact-duplicate tweet quality gate. Editable Writer and Reviewer prompts are checked for the new paraphrase policy.

The later usage regression verifies that a draft with unmapped claims still drops after at most two attempts, but does not mark token metadata unavailable for a semantic model call that never happened. The bounded-window tests distinguish ordinary partial context from a true budget-limited window and reject a false partial-window flag.

Original tests continue to cover one Writer revision, deterministic brand and format rules, source failures isolated by slot, Send fan-out, ordered aggregation, the one-call model limit, CLI contracts, exact CSV output, accepted-only visuals, and reviewer-score vetoes. Mocks prove those control-flow properties; they do not prove semantic accuracy. The 60-case real Ollama benchmark and updated six-slot run are separate evidence.

No extra semantic reconciliation call was introduced. Transport retries remain inside `LocalModel`; content revision remains at most one in LangGraph. A first-pass INSUFFICIENT_EVIDENCE still fails closed. A skeptical veto empties final support even when the first pass and context window favored support.

Real-model adversarial checks on the final prompts: the six source-text injection strings produced **0/6** false accepts (`injection-results.json`), with 6,156 prompt and 616 completion tokens recorded. The saved `thread_3` attempt-two claim reran through both passes as SUPPORTED with exact option `SCWE-028#2`, context offsets 400–659 in the pinned snapshot, and 2,432 prompt / 255 completion tokens (`thread3-reproduction.json`). The earlier attempt-one overclaim remains a justified rejection. These observations test specific cases, not universal resistance to attacks or false negatives.

The final 60-case replay produced 28/30 supported passes and 0/30 adverse false accepts. The independently frozen final v3 holdout produced 8/10 supported passes and 0/10 adverse false accepts. Both met the predeclared publication-side thresholds, though the two supported holdout recommendations rejected by the skeptic are real quality costs. No labels or hard gates were changed after inspecting the v3 predictions.

The first updated technical standalone run failed on a Reviewer contradiction and exported zero posts. `tech-reviewer-diagnostic.json` preserved both structured responses. After making tweet-array rendering explicit, a real Reviewer recheck approved the saved draft, and the complete rerun shipped one six-tweet piece (`output/semantic-context-quality-tech-calibrated/`, 96.748 seconds, 21,720 prompt / 1,940 completion tokens).
