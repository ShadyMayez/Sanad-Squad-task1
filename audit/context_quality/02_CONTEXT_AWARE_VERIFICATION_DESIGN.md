# Context-aware verification design

`SemanticVerifier` keeps the original two-pass architecture. The first pass receives the pinned source quote and exact, numbered source options. The second pass receives the selected options, the original atomic proposition and public sentence, the first pass's tentative decision, and bounded source windows around each selected option. Every window retains evidence ID, pinned snapshot SHA-256, source scope, absolute code-point offsets, exact text, and a truncation flag. Existing quotations are at most 1,127 characters, so initial-pass input is bounded by the curated KB; no full web page is passed.

`bounded_context` uses source span boundaries and up to two neighboring options on either side, with a 1,400-character cap and a 1,400 UTF-8-byte cap. Byte length is a conservative upper bound on tokenizer units for ordinary source text, not a measurement of actual Qwen tokens. The record exposes this upper bound and budget. It avoids crossing a `Remediation` section boundary. `window_partial` says the window does not contain the entire pinned quotation; `truncated` means the byte or character budget prevented including a requested neighboring span. A selected span longer than either cap stays intact and is marked truncated. Windows never join unrelated source IDs. Source offsets are derived from the already verified quote offsets. `context_errors` rechecks snapshot hash, source identity, offset range, exact text, optional partial flag, and recorded byte bound; export rechecks windows for accepted pieces. Older saved windows without `window_partial` remain readable.

Selected spans remain the proposed proof. A window can resolve a pronoun, list heading, or condition, and can expose counterevidence; mere proximity or keyword overlap never establishes a causal claim. The skeptic remains independent and may veto. Both first and skeptical decisions are persisted; a veto keeps proposed spans for diagnosis but empties final supporting spans. No extra model reconciliation call or Writer revision was added. Unresolved disagreement fails closed.

The prompt explicitly requires referent matching. A source sentence with multiple possible antecedents cannot prove a claim assigning its pronoun to one named entity. The semantic model can still make a wrong coreference decision; the supplemental ambiguity probes measure this known risk. The skeptic also distinguishes a source-attributed recommendation from an unsupported universal guarantee.

Schema migration is additive: `SemanticVerdict` now optionally contains `context_windows`, `proposed_supporting_spans`, `initial_pass`, and `skeptical_pass`. Old saved JSON remains valid because these fields have defaults. New accepted records undergo stronger context integrity checks in `export_run`. The final chain remains public sentence → atomic claim → exact option IDs and spans → snapshot and window offsets → both semantic decisions → Reviewer → export gate.
